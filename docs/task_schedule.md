# ピックR1！ タスクリスト & スケジュール

2日間（11/14 土 〜 11/15 日）で MVP「箱のQRをR1が読み取り → 分類先へ移動 → 可視化ツールで確認」を完成させ、発表する。

## 役割分担（4名・仮置き。名前を記入）

| 担当 | 名前 | 主担当 |
|---|---|---|
| A: ロボット制御 | | LocoClient / 腕動作 / 移動・実機検証 |
| B: 認識 | | カメラ取得・QR読取・Gemini画像認識 |
| C: 可視化ツール | | Webアプリ（ダッシュボード）・ログ連携 |
| D: PM・デモ設計 | | 現場セット・QR/箱準備・統合・発表資料 |

※ 実機は1台を取り合うため、**実機時間の割当表**を D が管理する（Day1後半は A 優先、Day2午前は統合優先）。

## MVP の定義（発表で見せるもの）

1. 箱に貼った QR を R1 のカメラで読み取る
2. QR の内容から分類先（例: 区画A / B）を判定
3. 所定の場所へ移動（箱を持つ動作が難しければ「分類先へ歩いて向かい、腕で指し示す」に縮小）
4. 作業ログがダッシュボードにリアルタイム表示（誰が・何を・どこへ・いつ）

**Must**: 1・2・4（読取→判定→ログ可視化）／ **Should**: 3（移動）／ **Could**: 箱を持つ・Gemini による商品認識・梱包（蓋閉め）は将来展開として発表で触れるのみ

## 共通仕様（案）

### イベント JSON（B/A → C）
※ 正式なデータレイアウトは [log_schema.md](log_schema.md)。以下は概要。
```json
{
  "ts": "2026-11-15T10:30:00",
  "robot": "R1",
  "event": "scanned | moving | arrived | error",
  "box_id": "B001",
  "zone": "A",
  "detail": "任意メッセージ"
}
```
送信先：`POST http://<devPC>:8000/events`

## リスクと対策

| リスク | 対策 |
|---|---|
| R1 カメラ映像が SDK から取れない | 外付けカメラ/スマホをR1に固定。早期（D1午前）に判明させる |
| 箱を持って歩くのが不安定 | 箱は持たず「読取→区画へ歩行→腕で指し示す」に縮小。箱運搬は将来展開 |
| QR 読取が不安定 | QRを大きく・白余白を広く・読取位置を固定。照明を一定に |
| 実機の取り合い | 実機時間割を D が管理。それ以外はモック/ダミーイベントで開発 |
| 会場ネットワーク不安 | ローカル完結にし、Gemini だけ外部依存。録画動画を保険に |
| 歩行時の安全 | 周囲に人を近づけない、緊急停止手順、`Move()` は短時間で `StopMove()` |
